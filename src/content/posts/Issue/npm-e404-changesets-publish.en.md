## Background

[`react-use-hook-kit`](https://github.com/practical-stack/react-use-hook-kit) is a React hooks package published to npm. The package uses Changesets in its [`Release` GitHub Actions workflow](https://github.com/practical-stack/react-use-hook-kit/blob/main/.github/workflows/release.yml) to create version tags and publish to npm.

On 2026-05-12, the release workflow failed while publishing [`react-use-hook-kit@0.1.1`](https://www.npmjs.com/package/react-use-hook-kit/v/0.1.1).

## The Problem

The failure was not in the build or packaging step. It happened during the Changesets publish step, where the npm registry returned `E404 Not Found` for the publish request.

```text
Publishing "react-use-hook-kit" at "0.1.1"
E404 Not Found - PUT https://registry.npmjs.org/react-use-hook-kit - Not found
The requested resource 'react-use-hook-kit@0.1.1' could not be found or you do not have permission to access it.
```

At first, I checked whether the package name, npm permissions, or token value itself was the problem. Those all turned out to be fine.

The following steps passed in GitHub Actions.

- `pnpm install --frozen-lockfile`
- `pnpm --filter react-use-hook-kit run build`

The tarball to be published was also generated correctly locally.

```bash
pnpm --filter react-use-hook-kit pack --pack-destination /tmp
pnpm --filter react-use-hook-kit exec npm publish --dry-run --access public --registry=https://registry.npmjs.org
```

The existing version was present in the npm registry.

```text
react-use-hook-kit@0.1.0
```

I temporarily added a `Verify npm auth` step to the workflow and checked the auth state inside Actions.

```yaml
- name: Verify npm auth
  run: |
    npm whoami --registry=https://registry.npmjs.org
    npm access list collaborators react-use-hook-kit --registry=https://registry.npmjs.org
  env:
    NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

The output looked correct.

```text
p-iknow
p-iknow: read-write
```

So this was not a case where the package was missing, `secrets.NPM_TOKEN` was wrong, or the npm account lacked publish permission.

## Root Cause

### Misleading Signals

The npm publish failure showed up as `E404 Not Found`. In practice, though, this does not always mean the package is missing. npm can return the same shape of error when authentication is not applied correctly to the publish request.

Another confusing part was that the existing publish step looked like it had a valid auth setup. It was passing `NPM_TOKEN` to [`changesets/action`](https://github.com/changesets/action).

```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GH_ACCESS_TOKEN }}
  NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

The package already existed in the npm registry, and both `npm whoami` and the collaborator permission check succeeded inside GitHub Actions. That made the failure more ambiguous. But those checks were run in a separate verification step where `NODE_AUTH_TOKEN` was passed directly. They did not prove that the actual Changesets publish step was using the same authentication path.

### Different Consumers Read Different Tokens

When [`actions/setup-node`](https://github.com/actions/setup-node) is configured with `registry-url`, it creates a temporary npm config on the runner and sets `NPM_CONFIG_USERCONFIG` in the workflow environment.

The publish step logs also showed the following environment values.

```text
NPM_CONFIG_USERCONFIG: /home/runner/work/_temp/.npmrc
NODE_AUTH_TOKEN: XXXXX-XXXXX-XXXXX-XXXXX
NPM_TOKEN: ***
```

That temporary `.npmrc` typically references `NODE_AUTH_TOKEN`.

```ini
//registry.npmjs.org/:_authToken=${NODE_AUTH_TOKEN}
```

The two token environment variables can point to the same secret value, but they are read by different consumers.

- `NPM_TOKEN`: the GitHub secret name expected by the [`changesets/action` publishing example](https://github.com/changesets/action#with-publishing). The Changesets action generally uses this value to prepare the `.npmrc` used for npm publishing.
- `NODE_AUTH_TOKEN`: the environment variable used by the [`registry-url` option in `actions/setup-node`](https://github.com/actions/setup-node#readme) and the [GitHub Docs npm publish example](https://docs.github.com/en/actions/tutorials/publish-packages/publish-nodejs-packages#publishing-packages-to-the-npm-registry). The `.npmrc` generated by `setup-node` references this value.

npm's own rules line up with this as well. According to the [npm Docs for `.npmrc`](https://docs.npmjs.com/cli/v8/configuring-npm/npmrc/), `.npmrc` files can substitute environment variables with the `${VARIABLE_NAME}` form, and `_authToken` must be scoped to a specific registry.

In this workflow, passing only `NPM_TOKEN` to the action was not enough. The process that actually performed the publish was not `changesets/action` itself, but `pnpm changeset publish` and `npm publish` running inside it.

In short:

```text
NPM_TOKEN
  -> read by changesets/action
  -> used to prepare the publish command

NODE_AUTH_TOKEN
  -> referenced by the .npmrc generated by setup-node
  -> used by the npm CLI when publishing to the registry
```

Because of that, the publish request reached the npm registry without sufficient authentication, and npm returned `E404 Not Found`.

## The Fix

I explicitly added `NODE_AUTH_TOKEN` to the Changesets publish step in [`release.yml`](https://github.com/practical-stack/react-use-hook-kit/blob/main/.github/workflows/release.yml).

```diff
 env:
   GITHUB_TOKEN: ${{ secrets.GH_ACCESS_TOKEN }}
   NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
+  NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

Both environment variables use the same GitHub secret, but passing both names satisfies the auth paths for both the action and the npm CLI.

The fix was committed in [`d0cdf9d ci: pass npm token to release publish`](https://github.com/practical-stack/react-use-hook-kit/commit/d0cdf9d), and [`Release run: 25724365449`](https://github.com/practical-stack/react-use-hook-kit/actions/runs/25724365449) succeeded afterward.

```text
Result: success
```
